# 项目指标说明与评测补全计划

更新日期：2026-11-01。本文统一现有指标的含义、结果范围和后续评测口径；本次仅补充文档，没有重新运行评测。历史结果来自 2026-10-29 的报告和保存产物。

具体执行设计见 [RAG 实验方案](EXPERIMENT_PLAN.md)，包含样本划分、实验分组、控制变量、人工评分与性能测试步骤。

## 1. 当前结论与适用范围

项目已有真实 RAGAS 评分、API 回归检查和工程验收记录，但尚无覆盖当前默认应用链路的完整质量、性能和成本基线。

当前较完整的质量实验为 **100 篇文档、634 个文本块、50 道题、每题 Top-5**。使用 BGE-small 稠密向量检索和受约束的回答生成，未运行应用中的 BM25、RRF、BGE reranker 或 LangGraph 自适应纠错。不能将该结果直接归属于默认 BGE-large 混合检索链路，也不能据此宣称重排或纠错带来提升。

50 道题来自 50 个不同文件，标准答案通过模型辅助生成、逐字证据检查和再次模型校验，尚未逐题人工审核。题目均基于可回答文档，不包含独立设计的无答案测试集。

## 2. 已有质量与耗时结果

| 指标 | 含义与口径 | 50 题结果 | 解读限制 |
|---|---|---:|---|
| Faithfulness（忠实度） | 模型判断回答中的事实陈述是否受检索上下文支持；概念口径为受支持陈述数 / 回答事实陈述数，再对题目取均值 | 0.9064 | 有依据不代表标准答案完整，也不等于人工正确率 |
| Context Recall（上下文召回） | 模型判断标准答案中的信息是否能由检索上下文支持；概念口径为受支持的参考陈述数 / 参考陈述数，再对题目取均值 | 0.9000 | 不是基于相关文档或块标注计算的 Recall@K |
| Response Relevancy（回答相关性） | 根据回答反向生成问题，结合问题向量相似性等计算相关性 | 0.7823 | 不是“78.23% 的回答正确”；本次使用本地 BGE-small 和 strictness=1 |
| 检索与生成平均耗时 | 对每题记录的 seconds 取算术平均 | 1.264 秒 | 不是应用 API 延迟或并发性能，不包含 RAGAS 评审 |
| 单题最短 / 最长耗时 | 上述 seconds 的最小 / 最大值 | 0.547 / 2.453 秒 | 最大值不能代替 P95 或 P99 |
| 评分完整性 | 50 题 × 3 项指标的完成情况 | 150 项完成，0 项缺失 | 仅代表评分执行完整，不代表质量达标 |

RAGAS 版本为 0.4.3。具体陈述拆分、判定和边界处理以该版本实现为准。Faithfulness 和 Context Recall 使用配置的聊天模型评审；相关性额外使用 embedding。均值按题目等权计算，不能把模型评分解释为业务准确率。

`Response Relevancy` 是报告名称；当前汇总 JSON 使用 `answer_relevancy` 字段，两者在这批产物中对应同一项指标。比较实验时应统一名称映射，并保留原始列名。

计时范围由 [build_ragas_pilot.py](../scripts/build_ragas_pilot.py) 确定：从单题查询向量化开始，包含 NumPy 向量打分、Top-K 选择、提示构造和聊天接口请求，结束于取得回答。语料加载、模型初始化、文档向量化及索引构建不在该单题计时内；这次回答检索不是经应用 API 或 Milvus 执行。

原始证据与详细分析：

- [50 题报告](RAGAS_EVALUATION_50_20261029.md)：设置、失败样例、限制和复现命令。
- [5 题先导报告](RAGAS_EVALUATION_20261029.md)：较早的独立小样本实验，不能与 50 题均值直接拼接或据此宣称提升。
- [机器可读汇总](../evaluation/results/run-20261029/ragas-50-summary.json)。
- [逐题评分](../evaluation/results/run-20261029/ragas-50-scores.csv)及[上下文与回答](../evaluation/results/run-20261029/ragas-50-responses.json)。
- [50 题数据集](../evaluation/datasets/ragas-50-100docs.jsonl)。

运行产物位于本地 `evaluation/results/`，其他检出环境可能没有这些文件；复核时应随报告保留对应产物。

## 3. 已有 API 回归检查

[evaluate_rag.py](../scripts/evaluate_rag.py) 支持 classic、agent、adaptive、graph1、graph2，逐题调用真实 `/ask` API，保存下列检查。它们主要用于回归定位，不能代替语义质量评估。

| 字段 | 当前实现口径 | 注意事项 |
|---|---|---|
| `status` | 返回状态是否等于样本声明的 `expect_status` | 未声明时为 null |
| `expected_page_coverage` | 被引用来源的页码与期望页码交集大小 / 去重后的期望页码数 | 未声明时为 null；目前只比较页码，跨文件同页码可能混淆，不能当作跨文档证据召回 |
| `expected_terms_present` | 所有期望关键词是否均出现在答案中 | 单题布尔值，不是语义准确率；没有期望词时也为 true |
| `forbidden_terms_absent` | 答案是否不含任何禁用词 | 字符串检查不能覆盖全部错误表达 |
| `minimum_citation_files` | 被引用的不同文件名数是否达到要求 | 不能证明引用支持答案；默认要求为 0 |
| `required_trace_nodes` | 是否包含全部要求的流程节点 | 证明节点出现，不证明节点决策正确 |
| `all_declared_checks_passed` | 所有非 null 检查值均须满足 `value is True` | 当前页码覆盖是浮点数，即使为 1.0 也不是布尔 True；有页码要求的样本不能直接靠此字段判断通过，需先修正聚合逻辑 |
| `seconds` | 成功请求从计时开始至响应解析、检查完成的耗时 | 包含客户端开销；错误记录目前不保存该字段 |

后续统计关键词通过率时，分母只应包含明确声明了关键词要求的样本；其他条件检查同理。请求错误必须另报数量和比例，不应静默排除后声称全部通过。

[100 文档验收记录](ACCEPTANCE_100DOCS_20261029.md)中的 32.36 秒是向量化、索引及检索总耗时，0.805954 是单条命中的余弦相似度，均不是回答准确率。该次 AES API 回归返回 HTTP 404，没有有效答案；应记作请求失败，而不是回答正确率为 0。测试通过数量与回答质量指标也应分别报告。

## 4. 待补指标及统一口径

以下为后续实施规范，**尚无本文确认的实测结果，也不是现有脚本已全部支持的功能**。

### 4.1 检索质量（高优先级）

先为每题标注相关文档或块的稳定 ID，并明确按文档还是按块评估，不能混用。设相关集合为 R，前 K 个去重检索结果为 T_K：

| 指标 | 约定计算方式 | 用途 |
|---|---|---|
| Recall@K | `|R ∩ T_K| / |R|`，逐题计算后取均值 | 是否找全相关证据 |
| Precision@K | `|R ∩ T_K| / K`；不足 K 条的空位按不相关计 | 返回材料中的噪声程度 |
| Hit@K | 前 K 条至少有一条相关为 1，否则为 0，再取均值 | 是否至少命中一条证据 |
| MRR@K | 首条相关结果排名为 r 时计 `1/r`；前 K 无相关结果计 0，再取均值 | 首条有效证据是否靠前 |
| nDCG@K | `DCG@K / IDCG@K`，其中 `DCG@K = Σ(2^rel_i - 1)/log2(i+1)` | 使用分级相关性标签衡量排序质量 |

建议固定报告 K=1、3、5、10。nDCG 的相关性等级需预先定义，例如 0=不相关、1=部分支持、2=直接支持。R 为空或 IDCG 为 0 的无答案题不参与上述质量均值，应单独报告数量并进入拒答评测。现有来源证据尚不等于全库穷尽相关块标注；未完成标注前不要把文档来源命中当作完整 Recall@K。

### 4.2 答案、引用与拒答（高优先级）

| 指标 | 建议口径 |
|---|---|
| 人工回答正确率 | 满足预先定义的关键要点且无实质错误的回答数 / 有效返回的可回答题数；另报将请求失败计为未成功的端到端成功率 |
| 引用支持率 | 经审核确实支持对应结论的“结论—引用”配对数 / 全部已给出的配对数 |
| 引用覆盖率 | 有有效引用支持的需证据事实结论数 / 全部需证据事实结论数 |
| 正确拒答率 | 无答案题中有效返回且正确拒答的题数 / 全部无答案题数 |
| 误拒答率 | 可回答题中有效返回但拒答的题数 / 全部可回答题数 |

HTTP 错误不算正确拒答，应单独计入请求失败率。无引用、无事实陈述等零分母情况标为 N/A，并报告样本数，不能默认满分。正确率需保存逐题人工判定、理由和引用证据；有争议样本需复核。

现有 50 题中 8 道包含资料不足等表述，只是文本分析结果，不能直接视为已标注的误拒答率。需要新增独立无答案题，并覆盖检索遗漏、真实无答案、资料冲突等情况。

### 4.3 性能、成本与运行可靠性（中优先级）

| 维度 | 待补指标与记录要求 |
|---|---|
| API 延迟 | 客户端发起请求至完整响应的 P50/P95/P99；分模式、冷启动/热启动和并发档位报告，写明分位数算法 |
| 阶段耗时 | 查询向量化、检索、重排、生成、改写/重试及评估阶段分别计时 |
| 吞吐与失败 | 完成请求数 / 测试墙钟秒数、成功请求吞吐、失败请求数 / 总请求数；保留超时和错误类型 |
| 调用成本 | 每题输入/输出 token、LLM/embedding 调用次数、重试次数；按记录的模型单价和日期换算成本，区分在线问答与离线评审 |
| 入库可靠性 | 文档处理成功率、处理耗时、队列等待时间、重试次数，以及源文件/块/索引数量一致性 |

并发压测需固定硬件、模型部署位置、语料规模、请求分布、预热方式和超时设置。成功与失败请求分别报告耗时及样本数，不能只报告成功请求平均值。当前 50 题均值不构成服务 SLA。

## 5. 完整链路对照实验

建议在同一份经过复核的数据集和固定语料快照上，依次评测：

| 组别 | 检索与生成配置 | 当前状态 |
|---|---|---|
| 历史参考 | BGE-small Dense Top-5 + 受约束生成 | 已有 50 题结果，属于独立脚本路径 |
| A | 固定 embedding 的 Dense + 固定生成流程 | 待测 |
| B | 与 A 相同 embedding，增加 BM25 + RRF | 待测 |
| C | B 增加 BGE reranker | 待测 |
| D | C 增加自适应查询规划、改写和纠错 | 待测 |

A/B/C/D 应固定生成模型、提示词、语料、问题集、最终上下文数和可比较的候选预算，并记录各组实际配置。更换 BGE-small/BGE-large 应另设对照，避免把模型变化与检索策略变化混为一谈。自适应流程无法固定的调用次数和提示变化应明确记录。仅切换 API `mode` 不一定实现上述模块消融，需要检查或补充配置支持。

所有组同时报告质量、耗时、成本、失败数和逐题差异。优先复测现有应变硅、ALD、等离子体刻蚀等低分样本，同时保留独立测试集，避免只对已知失败题调优。跨文档、多跳、多轮、无答案、冲突材料和表格/图表题分别统计，不能只给总体均值。

## 6. 报告与验收约定

每次实验至少保存：

1. 运行 ID、时间、代码版本及未提交改动状态、语料清单与摘要、数据集版本和标注方法。
2. embedding、reranker、生成和评审模型的明确名称/版本，RAGAS 版本、提示词版本及关键参数；不保存 API 密钥。
3. 硬件与运行环境、检索候选数和最终 Top-K、联网开关、超时、重试与并发配置。
4. 逐题原始回答、实际上下文、引用、状态、耗时、评分和错误，以及汇总时使用的分母。
5. 质量均值、分布、按题型结果和失败分析；对比实验可按同题配对 bootstrap 报告差值的 95% 置信区间。

当前没有已确认的质量验收阈值或性能 SLA。报告中的“低于 0.8”是分布统计，不代表项目已经规定 0.8 为通过线。先完成基线，再结合使用场景确定质量下限、允许回归幅度、延迟和成本预算，随后固化为回归门槛。

[evaluate_ragas.py](../scripts/evaluate_ragas.py) 遇到输入请求失败或缺失分数会报错，不能把不完整评分当作通过。若后续允许部分结果汇总，必须同时展示计划题数、请求成功数、评分有效数和未完成原因，并明确结果不完整。

推荐补全顺序：修正回归聚合口径 → 人工复核测试集并补无答案题 → 运行同题完整链路对照 → 增加排名、引用和拒答指标 → 完成性能与成本基线 → 确定验收阈值。
